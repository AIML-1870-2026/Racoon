# Product Review Generator — Spec

---

> ⚠️ **Disclaimer — For LLM Exploration Only**
>
> This tool is intended solely for learning about and experimenting with large language models. Output from this tool **must not** be posted, submitted, or published as a real product review on any platform (Amazon, Yelp, Google, etc.) or used in any commercial context.
>
> **Why this matters — the FTC's fake review ban:**
> The FTC's Consumer Review Rule (16 CFR Part 465) took effect on October 21, 2024 and explicitly covers AI-generated fake reviews. The rule prohibits the creation, sale, or dissemination of fake reviews, including those generated by AI. Violations can result in federal lawsuits and civil penalties of up to $53,088 per violation. There is no private right of action — only the FTC can enforce these rules, but enforcement actions have already begun, with the FTC issuing cease-and-desist warning letters to companies in December 2025.
>
> Using AI-generated content as genuine consumer reviews is deceptive, harms consumers, and exposes individuals and businesses to significant legal liability.

---

## Overview

A web-based tool that uses OpenAI language models to generate natural, unstructured product reviews. Users provide product details, configure generation settings, and receive rendered markdown output they can copy or export.

---

## Features

### 1. OpenAI Models Only

- Model selector limited to OpenAI's chat completion models (e.g. `gpt-4o`, `gpt-4o-mini`, `gpt-4-turbo`, `gpt-3.5-turbo`)
- Model list fetched dynamically from the OpenAI `/v1/models` endpoint using the loaded API key, filtered to chat-compatible models
- Selected model persists for the current session only (in-memory state)

---

### 2. Unstructured Review Output

- Reviews are generated as free-form prose — no bullet points, rating breakdowns, or structured templates
- The prompt instructs the model to write naturally, as a real customer would, with varied sentence length, casual language, and organic opinions
- No post-processing or formatting applied to the raw model output

---

### 3. Markdown Rendering & Editing

- All model output is rendered as markdown in the UI (using a library like `marked.js` or `react-markdown`)
- Supports bold, italic, headers, and blockquotes in case the model naturally uses them
- Once generated, the review is displayed in a **read/edit toggle**:
  - **Read mode** — rendered markdown, clean and readable
  - **Edit mode** — plain text editor (textarea) pre-filled with the raw markdown output; user can freely modify the content
- Switching back from edit to read mode re-renders the updated markdown
- A "raw text" toggle lets users view the unrendered output
- Copy-to-clipboard button copies plain text (strips markdown symbols), reflecting any edits the user has made

---

### 4. API Key Loading

Users can provide their OpenAI API key via three methods:

#### a. Paste In
- A text input field in the settings panel accepts a key pasted directly
- Key is masked after entry (password field)
- Stored in memory only for the current session; discarded on page refresh

#### b. `.env` File Upload
- User uploads a `.env` file
- Parser extracts the value of `OPENAI_API_KEY=...`
- File is read client-side only; never transmitted anywhere except directly to the OpenAI API

#### c. `.csv` File Upload
- User uploads a `.csv` file
- Parser looks for a column named `api_key`, `OPENAI_API_KEY`, or `key` (case-insensitive) and reads the first non-empty value
- File is read client-side only

**Key handling rules:**
- The active key is held **in memory only** — never written to `localStorage`, `sessionStorage`, cookies, or any other persistent store
- The key lives in a single private variable (e.g. a React ref or a module-scoped variable) and is never serialized or logged
- Refreshing or closing the page permanently discards the key; the user must re-enter it each session
- A "Clear Key" button explicitly nulls the in-memory variable and resets the input field
- No key is ever displayed in full after entry, logged to the console, or sent anywhere other than the `Authorization` header of requests to `api.openai.com`

---

### 5. Sentiment Control

Rather than a single global tone, sentiment is configured per aspect of the review. Each aspect gets its own continuous **slider** ranging from Negative (0) to Positive (100), with Neutral at the midpoint (50).

#### Overall sentiment slider
- A single top-level slider sets the general tone of the entire review, independent of any aspect
- Same 0–100 scale and 5-band label mapping as per-aspect sliders
- Injected into the system prompt as the baseline tone, e.g.:
  > "Overall tone: somewhat positive. Then apply the following per-aspect adjustments..."
- Defaults to **100 (very positive)** on load
- Included in the "Reset all" action

#### Default aspects
| Aspect | Description |
|---|---|
| Pricing | Value for money, cost vs. quality perception |
| Usability | Ease of use, learning curve, UX quality |
| Shipping & Delivery | Speed, packaging, condition on arrival |
| Build Quality | Materials, durability, finish |
| Customer Support | Responsiveness, helpfulness |

#### Custom aspects
- A user can add additional aspects via a text input (e.g. "Battery life", "Flavor", "Installation")
- Each added aspect gets its own sentiment control
- Aspects can be removed individually

#### Prompt injection
- Slider values are mapped to descriptive labels before being injected into the system prompt:

| Range | Label |
|---|---|
| 0–20 | very negative |
| 21–40 | somewhat negative |
| 41–59 | neutral |
| 60–79 | somewhat positive |
| 80–100 | very positive |

- All aspect/label pairs are serialized into the system prompt, e.g.:
  > "Write a product review with the following tones per aspect — Pricing: very negative, Usability: very positive, Shipping: neutral, Build Quality: somewhat positive. Weave these naturally into unstructured prose without labeling the sections."
- The model is instructed to blend all aspects into cohesive prose, not separate them into headers or lists

#### Defaults
- All sliders default to **100 (very positive)** on load
- A "Reset all" button returns every slider to 100

---

### 6. Tone Selection

- A horizontal slider lets the user select the writing tone of the review, distinct from sentiment (which controls positivity/negativity; tone controls *how* it is expressed)
- The slider snaps to discrete tone positions, with the tone name displayed as a label above or below the thumb

#### Tone sequence (left to right)

| Position | Tone | Description |
|---|---|---|
| 1 | Serious | Measured, formal, matter-of-fact |
| 2 | Neutral | No strong stylistic voice |
| 3 | Disappointed | Sad, let-down, subdued |
| 4 | Confused | Uncertain, questioning, back-and-forth |
| 5 | Humorous | Lighthearted, witty, may include jokes |
| 6 | Sarcastic | Dry, ironic, says one thing but implies another |
| 7 | Excited | Enthusiastic, energetic, lots of emphasis |
| 8 | Angry | Frustrated, blunt, emotionally charged |

- Selected tone is injected into the system prompt alongside sentiment, e.g.:
  > "Write the review in an excited tone. Overall sentiment: very positive..."
- Defaults to **Neutral** (position 2) on load
- Tone and sentiment are independent — e.g. a humorous tone with negative sentiment produces a sardonic, funny complaint

---

### 7. Response Length

- A slider controls the approximate length of the generated review
- Scale runs from **Short** to **Long** with labeled positions
- Slider value maps to a word count range injected into the system prompt:

| Position | Label | Target length |
|---|---|---|
| 0–25 | Short | ~50–100 words |
| 26–50 | Medium-short | ~100–200 words |
| 51–75 | Medium-long | ~200–350 words |
| 76–100 | Long | ~350–600 words |

- Injected into the system prompt as a soft target, e.g.:
  > "Write the review in approximately 200–350 words."
- Treated as a guideline rather than a hard limit to preserve natural prose flow
- Defaults to **50 (Medium-short)** on load

---

### 8. Disclaimer Banner

- A non-dismissible banner is displayed at the top of the page, below the app title
- Contains a condensed version of the disclaimer: intended use, FTC rule reference, and penalty amount
- Styled prominently (e.g. amber/warning color) to ensure it is not overlooked
- Links to the full FTC Consumer Review Rule page for users who want more detail

## Out of Scope

- Non-OpenAI model providers (Anthropic, Gemini, etc.)
- Backend / server-side components
- User accounts or review history
- Structured review templates or rating systems
- Bulk generation

## Tech Stack (Suggested)

| Concern | Choice |
|---|---|
| Framework | React or plain HTML/JS |
| Markdown rendering | `marked.js` or `react-markdown` |
| API calls | `fetch` to `api.openai.com` directly from browser |
| Key storage | In-memory only (module-scoped variable or React ref) |
| File parsing | Native `FileReader` API |
